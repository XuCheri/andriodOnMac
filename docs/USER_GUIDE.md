# 双向投屏用户指南 · 0.2.0-preview.1

## Mac 安装

需要 Apple Silicon（M1 或更新）及 macOS 13+。从本项目 GitHub Release 下载 DMG，打开后将 AndroidOnMac 拖到“应用程序”。ZIP 版本解压后同样移动到“应用程序”。无需安装 Homebrew、ADB 或 scrcpy。

当前预览包使用 ad-hoc 签名，**没有 Developer ID 签名或 Apple 公证**。首次打开时系统可能拦截：确认下载来源与 Release 的 SHA-256 后，先尝试打开一次，再到“系统设置 → 隐私与安全性”，找到 AndroidOnMac 的提示，按“仍要打开”并确认。仅在你确认这是自己信任的发行包时操作。

不要关闭 Gatekeeper、关闭系统保护或执行批量移除隔离属性的命令。企业设备若被管理员策略禁止，按组织流程处理。系统若明确报告恶意软件、文件损坏或签名与发布记录不符，不应将其当作普通未公证提示绕过。

macOS 若询问“本地网络”权限，允许 AndroidOnMac 访问后才能发现和连接局域网手机。

## 先选择投屏方向

| 方向 | 手机上看到什么 | 连接前提 |
| --- | --- | --- |
| 手机 → Mac | 手机自身正常使用，Mac 出现手机镜像窗口 | USB 调试；或 Android 11+ 无线调试，不装接收端 |
| Mac → 手机 | AndroidOnMac 接收端显示 Mac 画面 | Android 11+ 接收端；USB 或同一 Wi-Fi |

一次只运行一个方向。切换前先停止当前会话。以下“Mac → 手机”的扫码 Wi-Fi 与后面的“手机 → Mac 无线调试”是两套流程，不要混用配对码和端口。

## Mac → 手机：先安装接收端

推荐先用 USB 安装，Mac 发行包已包含接收端 APK。

1. 数据线连接 Android 和 Mac，开启手机 USB 调试，解锁并允许这台 Mac。
2. 在 Mac 选择“Mac → 手机”，刷新并选择已授权设备，点击“安装接收端”。手机出现安装确认时按提示操作。
3. 手机上应出现“AndroidOnMac 接收端”。这一步只完成安装，尚未开始传输画面。

也可直接安装 Release 附带的 `AndroidOnMac-Receiver-0.2.0-preview.1.apk`。只安装自己信任的发行包；更新需要与原安装包相同的签名身份。安装失败时先查看提示，不要默认卸载或清除已配对数据。

## Mac → 手机：权限与 USB 开始

1. Mac 界面点击“屏幕录制 → 授予权限”，在系统设置中允许 AndroidOnMac。根据 macOS 提示重新打开应用，再点“已完成授权，刷新状态”。
2. 选择“镜像屏幕”和要共享的显示器；画面是选中显示器的整个桌面，请把不准备共享的窗口移到其他屏幕或关闭。
3. 保持 USB 连接，选择正确的手机，点击“开始投屏”。接收端会自动打开；第一次连接仍需在 **Mac** 确认允许该手机。
4. 只有手机真正显示第一帧后，Mac 才会显示正在共享。授权成功或连接成功不等于已经出现画面。

更新 ad-hoc 预览构建后，macOS 可能不沿用旧授权。若应用仍显示未授权，在系统设置中重新开启 AndroidOnMac 的对应权限；开关已经开启时可关闭再开启，按系统提示重新启动，再刷新授权状态。

想从手机操作 Mac，还需在“辅助功能 → 授予权限”中允许 AndroidOnMac，并在开始前开启“允许手机触控”。未授予辅助功能权限时可以观看。若只想观看，关闭该开关后再开始会话。

## Mac → 手机：同一 Wi-Fi 扫码

接收端安装好后可以拔下数据线。**此流程不需要 Android 无线调试、ADB 配对码或配对端口。**

1. 两台设备接入允许互访的同一局域网。在 Mac 选择“同一 Wi-Fi”，确认画面来源后开始投屏。
2. 打开手机接收端，点击“扫描二维码”，允许扫码所需的相机权限，扫描 Mac 显示的二维码。
3. 在 Mac 确认新设备请求，然后等待手机显示画面。二维码包含本次连接凭据，不要转发或公开截图。
4. 已配对设备可尝试“连接已配对 Mac”；若 Mac 地址或本次监听端口改变，重新扫描当前二维码。接收端不会因此跳过证书身份核验。

macOS 询问本地网络权限时应按使用需求允许。访客网络、设备隔离、VPN 或多个网卡可能使两端无法互访；先确认使用同一个可互访网络，必要时改用 USB。手机没有相机或暂时无法扫码时，请改用 USB 连接。不要手工修改证书身份指纹来绕过校验。

## Mac → 手机：实验性扩展副屏

选择“扩展副屏”后开始投屏。手机连接时，Mac 创建一块独立桌面，默认放在现有显示器右侧。把 Mac 窗口拖到该桌面，或使用窗口菜单中的“移到 AndroidOnMac Android Display”，即可在手机查看；可用“显示器设置”调整排列。

副屏会显式选择请求的非 HiDPI 分辨率，不依赖 macOS 自动选取默认模式。1280 × 720 与 1920 × 1080 已在本机核对桌面尺寸和像素尺寸一致；系统没有对应模式时会明确报错，不会静默改用较小桌面。

手机上文字偏小时，停止投屏后选择“流畅优先”，使用 1280 × 720 副屏；相同字号的文字和窗口会占据更大的画面比例。标准画质使用 1920 × 1080。也可以直接在手机双指捏合放大，不必改变桌面分辨率。

副屏采用未公开的 macOS 虚拟显示接口，目前为实验性功能。若创建失败，停止后切回“镜像屏幕”。没有验证所有 macOS 版本、合盖或无实体显示器场景，不应将其视为稳定的硬件显示器替代品。

短暂网络断开时副屏可暂时保留，以减少窗口跳动；停止、连接恢复超时或退出会移除本应用创建的副屏。布局仅作用于本次应用会话，不写入永久显示布局。移除显示器时窗口可能被系统移回其他屏幕；停止前可先把重要窗口拖回主屏。

## 在手机上操作 Mac

- 轻点点击，双击执行双击，长按右键；单指始终拖动 Mac 内容。画面保持比例，黑边不属于可操作区域。
- 双指捏合缩放画面；放大后双指移动用于平移视口，适应屏幕时双指同向移动用于滚动 Mac 页面。菜单中的“适应屏幕”恢复完整桌面；“至少原始像素大小”避免画面小于视频原始像素尺寸。
- 竖屏底部保留“键盘”、“横屏”和“更多”。切换横屏自动隐藏标题、控制栏和系统栏，只有一个小“⋯”画面菜单；其中可打开键盘、切回竖屏、恢复适应屏幕或停止。系统边缘滑动可临时显示导航栏。横竖屏只改变手机布局，不改变 Mac 副屏分辨率。
- 先在画面中点选 Mac 的目标输入框，再点“键盘”，直接使用手机输入法输入，不需要先编辑整段文字再发送。中文拼音组词期间保留在手机输入法中，确认候选文字后才进入 Mac；回车、退格和 Delete 发送对应的 Mac 按键。该文字不借用或同步两端剪贴板。
- “更多 → 快捷键”提供常用 Mac 操作，包括方向键、复制、粘贴、撤销等。“粘贴”使用 Mac 自己已有的剪贴板，不会把手机剪贴板自动传过去。
- 文字和快捷键只在焦点窗口位于所选显示器时发送；系统启用安全输入时会拒绝文字／快捷键注入。先点选目标窗口，不能用它绕过密码、锁屏或其他系统限制。
- “更多”或横屏的“⋯”菜单还可切换全屏、调整本地声音或“停止共享”。观看期间保持接收端在前台。

USB 画面、点击拖动、独立副屏与此前的中文文字发送已经过真机确认；这不替代新手机键盘直输、中文组合输入和手动横／竖屏的专项验收，这些项目当前仍待完成。

“传输 Mac 音频”默认关闭，需在 Mac 开始前开启；接收端“更多”里的声音开关仅控制手机播放，不能代替 Mac 开启音频采集。某些受保护内容不允许捕获，不能保证所有 App 的声音可传输。音频失败会明确提示，不应把无声当作已经通过音频验收。

网络波动时先选“流畅优先”，并用 USB 对照测试。首帧时间、动态帧率和操作延迟是不同指标；当前没有经过可重复的端到端延迟验收。

## 停止、后台与安全边界

手机点击“更多 → 停止共享”、离开接收端进入后台、锁屏或返回退出，都会结束共享；返回后需要主动重新连接。Mac 锁定、切换用户或睡眠会停止共享。网络意外中断时按 1、2、4 秒间隔最多尝试三次恢复；主动停止后不自动重连。

连接采用 TLS 和固定证书指纹，新手机需 Mac 明确确认；只有 Mac 主动开始等待的会话才能连接。接收端将已配对身份加密保存在 Android Keystore 保护的存储中，不进行 Android 备份。“连接选项 → 忘记已配对 Mac”可清除手机侧配对。

程序不保存画面录像，不记录输入正文、剪贴板内容或配对秘密。它不是无人值守远控服务；授权设备在共享期间能看到选中桌面，并按已开启的权限操作。当前仅在 USB／同一局域网内使用。

新增 Mac → 手机已完成 USB 镜像、独立副屏及部分输入实测；Wi-Fi、新手机键盘、旋转、声音和 30 分钟稳定性仍以 [验收记录](ACCEPTANCE.md) 为准。短时帧率或辅助程序测试不能替代这些项目。

## 手机 → Mac：首次 USB 连接

1. 用支持数据传输的 USB 线连接 Mac 与手机；仅充电线无法使用。
2. 在手机“关于手机”连续点击版本号开启开发者选项，按系统指引启用“USB 调试”。
3. 解锁手机，确认“允许 USB 调试”提示。只有你自己的可信 Mac 才勾选“始终允许”。
4. 在 AndroidOnMac 刷新设备列表，选择已授权手机，开始镜像。

`unauthorized` 表示需要在手机上授权；`offline` 表示连接暂时不可用。先检查手机解锁状态、数据线和 USB 模式。部分小米/MIUI/HyperOS 机型还需要开发者选项里的“USB 调试（安全设置）”，其要求以手机实际提示为准。

## 手机 → Mac：Android 11+ 无线调试

Mac 与手机连接同一局域网，建议使用稳定的 5 GHz / 6 GHz Wi-Fi。在手机开发者选项中开启“无线调试”，然后点这一行的文字进入详情页；旁边的开关只负责开启。小米手机通常从“设置 → 更多设置 → 开发者选项”进入。

1. 点“使用配对码配对设备”，记录弹窗里的 IP、**配对端口**和 6 位配对码。
2. 在 AndroidOnMac 的无线配对界面填写这组配对信息，保持手机配对弹窗可见直到成功。
3. 回到手机“无线调试”的主页面，读取 IP 与**连接端口**，使用该地址连接。连接端口通常与配对端口不同，网络切换后也可能变化。
4. 设备出现在列表并显示就绪后，开始镜像。

如果应用“自动发现”列出了这台手机，可点“填入配对地址”或“填入连接地址”自动填写。VPN / 虚拟网卡可能让手机显示其他接口地址；应使用 Mac 能访问的局域网地址。配对弹窗重新打开后，配对码与端口可能改变，请以当前信息为准。

“配对成功”不代表镜像已经建立；“ADB 已连接”也不代表视频或音频已经开始。公司/访客 Wi-Fi 可能隔离设备或阻止 mDNS，需换到允许设备互访的可信网络，或使用手动连接地址。

如果画面突然断开，先回手机确认“无线调试”开关仍开启。0.1.0 预览版的 Xiaomi / Android 16 实测出现过手机保持 Wi-Fi 在线、无线调试却自行关闭的情况，触发原因还未确认。此时 Mac 无法仅靠重试重新开启手机端服务；请手动重开开关，再从已保存设备连接。需要稳定使用时可先用 USB。不要为此关闭锁屏、修改安全保护或把调试端口暴露到公网。

Android 10 及更早系统没有这套配对码流程；需要先 USB 授权后启用旧式 TCP/IP 调试。首版界面主要面向 USB 与 Android 11+ 无线调试；旧式模式不自动开放手机端口。

## 手机 → Mac：输入与声音

- 在镜像窗口内点击是触摸，拖动是滑动，鼠标右键返回，常用快捷键以 [scrcpy 官方快捷键](https://github.com/Genymobile/scrcpy/blob/v5.0.1/doc/shortcuts.md) 为准。
- SDK 模式的文字注入限于 ASCII 和部分字符。中文建议先在 Mac 复制，再在镜像窗口粘贴；不要依赖“逐键输入文本”的旧式粘贴处理中文。
- UHID 模式把 Mac 键盘作为手机的实体键盘，首次需在 Android 配置实体键盘布局与输入法；它不直接搬运 Mac 输入法候选栏。旧 Android 可能不支持 UHID，可切回 SDK。
- 剪贴板同步会把内容送到另一端的系统剪贴板；可在会话选项中关闭。项目不会记录剪贴板正文或配对码。
- Android 12+ 音频通常直接工作；Android 11 开始时需解锁；Android 10 及以前没有音频转发。某些应用拒绝音频/画面捕获时，界面不能突破该限制。
- 网络抖动时先选流畅画质，优先用 USB 验证基线。更高分辨率和码率不一定更顺滑。

## 手机不在身边

本预览版只处理 USB / 同一局域网。Mac 与一台 ECS 并不能自动访问处于其他网络、没有预先授权链路的 Android 手机。跨网需要手机所在网络里保持在线的受控网关，或经手机用户批准的临时设备端组件，并另行设计身份授权、加密、连接撤销和断线恢复。

本项目当前没有部署 ECS 服务、开放公网 ADB 端口或配置隧道。请勿把手机调试端口直接暴露到公网。
